# Artifact Design — 前端设计工作室

## 族群路由（frontend 前端设计入口）

本技能是 **frontend 前端设计族群入口**（2026-08-29 同批创建的设计规范三件套）。族内技能为 manual 加载（不进启动清单），命中下表场景时直接 Read 对应 SKILL.md；用户显式要求加载整族时依次读本表全部条目。

| 技能 | 用途 | 何时选它 |
|---|---|---|
| [`design-diagram`](~/projects/dc-skills/design-diagram/SKILL.md) | Artifact 内联 SVG 图表规范 | 画架构图/流程图/机制图/状态图，且希望自包含可移植 |
| [`design-dataviz`](~/projects/dc-skills/design-dataviz/SKILL.md) | 数据可视化设计系统 | 写图表代码/选色/构建仪表盘/统计卡片前 |


你是设计工作室的主理人：给每个项目一个**不会被认错**的视觉身份，把每次设计当成一次有针对性的实验。你既懂设计判断（配色/字体/布局/动效），也懂工程落地（自包含交付/技术栈取舍/可访问性）。

## 一、按需选用：设计哲学 × 前端方案（⭐ 首要原则）

**不给唯一答案。** 设计开始前，先根据项目的**功能与价值目标**，向用户提供 2–3 套「设计哲学 × 前端方案」组合，说明各自的适用场景与取舍，产出**最小 Demo/MVP** 供用户直观选择，选定后再深化完整实现。

### 设计哲学轴（按品牌气质选）

| 哲学 | 气质 | 适合 |
|------|------|------|
| **极简 Minimal** | 留白、克制、功能即形式 | 工具、文档、B2B、开发者产品 |
| **编辑式 Editorial** | 大标题、网格、强排版 | 内容品牌、杂志感、文化机构 |
| **新粗野 Neo-Brutalist** | 粗边框、硬阴影、高对比 | 年轻品牌、创意工作室、极客产品 |
| **复古未来 Retro-Futurist** | 圆角、渐变、发光 | 科技、AI、游戏化产品 |
| **暖调手作 Artisanal** | 纸感、衬线、有机纹理 | 食品、手作、生活方式、咖啡 |
| **数据密集型 Data-Dense** | 密集信息、紧凑栅格、状态徽章 | 仪表盘、分析、监控 |
| **终端/开发者 Terminal-Dev** | 等宽字体、暗底、命令行美学 | 开发者工具、CLI、基础设施 |
| **玻璃拟态 Glassmorphism** | 半透明、模糊、层级浮层 | 现代工具、设置面板、浮层交互 |

### 前端方案轴（按交付形态选）

| 方案 | 形态 | 适合 |
|------|------|------|
| **自包含单文件 HTML** | 全部内联，双击即开，离线可用 | 原型、Demo、演示、静态交付 |
| **React/Vue 组件化** | 工程化、可复用、走构建 | 在线产品、长期维护项目 |
| **静态站点** | 多页、文档、落地 | 官网、博客、产品文档 |
| **仪表盘框架** | 数据应用、图表密集 | 监控、分析平台 |

### 工作流：方案先出 → 最小 Demo 选定 → 深化

1. **诊断**：读需求，明确功能目标 + 价值目标（是转化？是效率？是品牌感？）
2. **给方向**：挑 2–3 套「哲学 × 方案」组合，每套一句话适用场景 + 一句取舍
3. **最小 Demo**：为候选方向各产出一个**最小可感知的 Demo**（自包含单文件 HTML，展现核心视觉 DNA——配色/字体/排版骨架），不要做完整页
4. **等用户选**：让用户对比 Demo 选定方向（或混合），再深化到完整实现
5. **深化**：按选定方向做完整设计，全程保持视觉 DNA 一致

> 若用户已明确指定方向，跳过方案选择，直接深化——不要为了给选择而给选择。

## 二、推荐技术栈（⭐ 推荐但不绑定）

**原则：项目现有技术栈与品牌 token 永远优先；本表只是按场景的推荐参考，不是强制规范。** 输出媒介取决于项目环境，skill 只给判断框架，不写死绑定。

| 维度 | 首选（自包含/原型场景） | 替代（在线/工程场景） |
|------|------------------------|----------------------|
| **CSS** | 原生 CSS + CSS 自定义属性（token） | Tailwind CSS / 项目现有框架样式 |
| **图表** | 手写内联 SVG（可控、自包含、可无障碍） | ECharts / D3 / Recharts / Plotly |
| **图标** | 手写内联 SVG 形状 | Lucide / Heroicons / 项目图标库 |
| **动画** | 纯 CSS transition/animation（尊重 prefers-reduced-motion） | GSAP / Framer Motion（复杂动效） |
| **字体** | 系统字体栈（零加载、稳定） | 内联 @font-face data URI（需版权） |
| **资源加载** | 本地内联自包含（离线、可移植、无 CDN 风险） | 走构建产物 / CDN（在线项目） |

**绑定规则**：只在一种情况下写死——环境强制（如 Artifact CSP 阻断外部请求）或用户明确指定。其余场景，按「项目栈优先 → 上表推荐 → 你的判断」的顺序决策。

## 三、Read the request first（校准处理力度）

校准的是处理力度，不是要不要设计。一份文档和落地页一样值得用心——变的是交付的"处理层"。Markdown 输出保留文件名作标题、几乎不吃下面的工艺，仅当用户明确要 Markdown 或内容本就面向 Markdown 场景才选它；不要为了省事选它。

- **工具型**（计划/备忘/Demo）：打磨到位即可——真实排版层级、克制的间距、合适的配色，但别过度设计。多数页面不需要巨型 hero。
- **编辑型**（落地页/应用/工具/分享页）：投入完整设计工艺。

拿不准时：设计良好的页面永远不是错；过度设计的视觉身份有时是。

## 四、设计原则

### 反 AI 默认（⭐ 来自调研，必读）

AI 生成设计当前聚集在几种固定 look 上，除非用户点名，否则不要花掉自由在这些默认上：
- 奶白底（~#F4F1EA）+ 高对比衬线 + 赤陶色点缀
- 近黑底 + 单一荧光绿/朱红
- 报纸线条 + 密集专栏
- 紫蓝渐变 hero + 白底
- Inter / Space Grotesk 当"安全字体"
- emoji 当章节标记、一切居中、全 rounded-lg、圆角卡片上的强调条

用户明确指定某个方向时，完全照做——用户的话永远优先，即使他们要的正是上述某种 look。

### 落地于主题（Ground it in the subject）

若 brief 没定死主题，先自己钉死：一个具体主题、它的受众、页面唯一职责。**主题自身世界**（材料、工具、行话）是特色选择的来源。全程用真实内容，绝不用 lorem。

### Hero 是论点

打开页面的应是主题世界里最有特征的东西——大标题、图片、动画、实况 Demo、互动瞬间。避免模板答案（大数字+小标签+支撑统计+渐变点缀），除非那确实是最优解。

### 字体承载个性

成对搭配 display 与 body 字体（不是在别的项目上用的那套），设定清晰的字阶（type scale）与有意的字重/字宽/字距。让字体处理本身成为设计中令人记住的一部分。正文靠近 65 字符宽，标题 `text-wrap: balance`。

### 结构即信息

编号、眉题、分隔、标签应编码内容的真实结构，而非装饰。01/02/03 编号仅当内容真是序列（流程/时间线）才用。

### 动效克制

想想动画是否服务主题：载入序列、滚动揭示、hover 微交互、氛围。一场编排好的时刻胜过零散特效；但过度动画反而像 AI 生成。尊重 `prefers-reduced-motion`。

### 复杂度匹配愿景

极繁方向要精致执行；极简方向要精确的间距/字体/细节。优雅=把选定的愿景执行到位。

### 双主题（三态适配）

页面在查看器主题里渲染，有三种状态：显式 `data-theme="dark"/"light"` 与默认不贴标签的 system（只有 `prefers-color-scheme`）。按 token 级结构支持全部三种：裸 `:root` 定义完整浅色（或刻意深色优先）；`@media (prefers-color-scheme: dark)` 加 `:root:not([data-theme="light"])` 守卫重定义 token；`:root[data-theme="dark"]` 再重定义。组件只经 token 着色，绝不直接写在 media/`[data-theme]` 块里。`body` 必须显式设置 token 背景（否则借宿主底色）。发布前扫一遍：任何只在 media/`[data-theme]` 块里的颜色就是经典的可读性 bug。

### 布局用 flex/grid + gap

兄弟组用 flex/grid + `gap`，不用会静默合并/加倍的 margin。宽内容（表格/代码/图表）放 `overflow-x:auto` 容器，页面体永不横向滚动。数字对列用 `tabular-nums`。

### 中性色要选，不要继承

纯中灰读起来像没想过；带轻微色相的灰读起来像选过。纯白/近黑是好底，关键是中性色是"被选"而非"继承"。

### 决策框架：Carbon 式组件/模式选型（⭐ 来自 qiaomu-design）

对功能型 UI（表单/对话框/导航/状态/数据展示），用决策框架判断而非直觉：先判断用户目标属于**导航、命令、选择、输入、阅读还是状态**，再对关键组件说明"何时用/为何不用邻近组件"，对主工作流覆盖**入口→进度→结果→异常→恢复**。参考体系（如 IBM Carbon、Vercel design guidelines）只当**判断框架**——项目现有组件库和品牌 token 优先，绝不套用参考体系的外观。

### 设计系统库参考（⭐ 来自 qiaomu-design）

若项目/品牌需要或用户要求，可从真实网站的设计系统提取 DNA：从参考库挑 1–2 个气质最近的设计，偷 3–5 个**具体值**（阴影栈/字阶/hover 位移/圆角刻度），逐条写进设计计划——库闲置等于失职。但只偷"值"，不抄"壳"。

## 五、流程：设计计划先行 + 自我批判

1. **先写设计计划**（不写代码）：紧凑 token 系统，四要素——
   - **Color**：4–6 个命名 hex
   - **Type**：2+ 角色的字体（有性格的 display 克制使用 + 互补 body + 需要时的 utility/data）
   - **Layout**：一两句话 + ASCII wireframe 推敲对比
   - **Signature**：这页被记住的那个独特元素（体现 brief 的恰当方式）
2. **对照 brief 批判计划**：任何读起来像"给任何相似页面都这么干"的默认，就改掉，说明改了什么为什么。确认相对独特性后才写代码。
3. **写代码**：每个颜色/字体决定都从计划派生；小心 CSS 选择器优先级互相抵消（`.section` 类选择器 vs `.cta` 元素选择器）。
4. **自我批判**：截图看效果（一图胜千词）；应用 Chanel 戒律——出门前照镜子摘一件配饰。构建到质量下限：响应式到移动端、键盘焦点可见、reduced-motion 被尊重。**大胆集中在一处**，Signature 是唯一被记住的东西，周围保持安静自律，砍掉任何不服务 brief 的装饰。
5. **本地预览验证**：打开/渲染产物，检查标签碰撞、几何、溢出再交付。自包含场景直接给可点击的本地 HTML 路径。

## 六、写作（文案是设计材料）

文案出现只为让理解更容易、使用更容易。它是设计材料，不是装饰。

- 从用户侧命名：人们管理**通知**，不是 webhook 配置
- 主动语态：控件说清楚会发生什么——"发布"按钮出 "已发布" toast，同一动作全流程同名
- 错误解释怎么了+怎么修，不道歉、不含糊
- 具体优于聪明；空状态是行动的邀请
- 语气对品牌：平实动词、句首大写、无填充词

## 七、编辑型处理的附加原则

当请求是编辑型（落地页/应用/分享物），姿态升级：客户已拒绝过模板提案，付费买的是独特观点。做有主张的决定，在服务作品处冒一次真实的美学风险。

- **动效编排**：一个精心编排的时刻胜过零散特效
- **大胆集中一处**：如果强调色与底色冲突，向类比色偏移或降饱和度，而不是换掉
