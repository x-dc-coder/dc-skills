> 逻辑 ID：`docs.specs.farm-redesign-roadmap`（manifest 登记，双轨制稳定 ID）  
> 状态：**现行基准（active）** · 制定日期：2026-10-14 · 事实基线版本：dc-skills master  
> 依据：GPT-6-Astra 顶层架构仲裁、三路专家交叉分析（GLM-5.3 / Atria-Dawn-Preview / Grok-4.7）及用户十大议题指示。

## 一、架构愿景与重构核心目标

将 `dc-skills` 从单一的“本地 SKILL 软链分发器”，升级为全机统一的**“能力资产治理平台（Universal Capability Platform）”**。

### 核心设计原则
1. **统一资产三层模型**：
   - **声明层（Spec / Map）**：`agent-map.yaml` 作为全机能力的唯一事实源，声明期望态。
   - **编译层（Compiler）**：`skills-sync`、`family-apply`、`mcp-apply` 安全物化到各 Agent 专属配置与目录。
   - **巡检层（Doctor）**：`assets-doctor` 持续静态对账与健康检查，提供退出码分级的防退化网。
2. **全机技能三桶治理（All-Machine Skills）**：
   - 第一桶（主库托管）：`~/projects/dc-skills/`，通过农场软链分发。
   - 第二桶（平台内置）：`~/.grok/bundled/skills/` 等，建立基线与同名覆盖/禁用机制。
   - 第三桶（插件与外部）：`~/.claude/plugins/` 等，建立对账索引，防止命名空间冲突。
3. **能力包内聚族群（Family = Skill + MCP + CLI）**：
   - 族群不再仅是技能分组，而是声明包含必需 CLI、绑定的 MCP 和 Member Skills 的强类型依赖闭环。
4. **正交控制与三态模型**：
   - 彻底解耦“文件可见性（Mounting）”与“上下文注入（Prompt Injection）”。
   - 支持 Auto（随上下文自动注入）、Manual（不进上下文，`/name` 手动调用）、Unmounted（未挂载）三态。

## 二、四阶段工程演进路线图

```
阶段一：需求与资产边界定稿 ──► 阶段二：统一机制与编译器设计 ──► 阶段三：TDD 测试与巡检重构 ──► 阶段四：渐进实施与全机收拢
  (契约冻结 / 资产基线)           (agent-map / mcp-apply)       (测试网先行 / 错误定义)       (分批演进 / 零停机)
```

---

### 阶段一：需求分析与全机资产治理边界定稿

**目标**：不修改任何生产代码，对全机资产（Skill、MCP、CLI）建立权威清单与对账基线，冻结重构契约。

- **工作内容**：
  1. 对齐全机 34 个主库技能、22 个 Bundled 技能、各类插件技能的分类与纳管范围。
  2. 确立 `AGENTS.md` 统一项目指令标准，明确 `MEMORY.md` 跨 Agent 共享边界（私有工作记忆 vs 共享知识库）。
  3. 冻结 `agent-map.yaml` 扩展 Schema 设计（族群 `requires`、`standalone` 手动声明、`mcps` 统一清单）。
- **交付物**：
  - 权威资产对账表与 Schema 规范说明。
  - `docs/specs/全资产治理.md` 核心架构文档。
- **退出门槛**：
  - 每项需求在测试集上有确切落点；资产覆盖盲区有清单；架构契约正式冻结。

---

### 阶段二：建立统一技能农场机制与多 Agent 编译契约

**目标**：完成核心编译工具链改造，具备多 Agent 中立生成与配置分发能力。

- **工作内容**：
  1. **状态解耦**：重构 `scripts/family-apply.py` 与 `scripts/skills-sync`，实现 `iter_members()` 与 `resolve_load()` 抽象解析，彻底解除 `load-mode: manual` 强绑 `role: member` 的限制，支持独立技能声明 `load-mode: manual`。
  2. **多 Agent 兼容生成**：`family-apply` 统一生成 `disable-model-invocation: true`（Grok/Claude）与 `openai.yaml`（Codex）。
  3. **MCP 统一分发器**：新建 `scripts/mcp-apply.py`，支持基于安全标记块（`# BEGIN/END dc-farm mcp`）向 Grok（`config.toml`）、Claude（`.claude.json`）、Codex 分发 MCP 配置。
- **交付物**：
  - `scripts/family-apply.py`（重构版）。
  - `scripts/skills-sync`（重构版，放宽断言）。
  - `scripts/mcp-apply.py`（新增）。
- **退出门槛**：
  - 同一份清单在 Dry-run 下生成确定性输出；不支持的语义显式报错；不修改尚未迁移的生产配置。

---

### 阶段三：测试网先行（TDD）与 assets-doctor 重构

**目标**：严格遵循 TDD 规范，先写失败测试与断言规则，再跑通功能，建立坚固的防退化网。

- **工作内容**：
  1. **单元测试与集成测试套件**：
     - `tests/test_family_load_mode.py`：测试 standalone 手动模式、member 默认模式、entry 自动模式的生成一致性。
     - `tests/test_skills_sync_families.py`：测试多 Agent 软链对齐与冲突检测。
     - `tests/test_mcp_apply.py`：测试标记块合并、外部配置保留、幂等性与回滚机制。
  2. **`assets-doctor` 巡检器重构**：
     - 增加 Bundled 技能状态对账断言。
     - 增加独立 Manual 技能三标记一致性断言。
     - 增加 MCP 工具数基线检查（`tool_count_baseline`）与非法注入检测。
     - 增加族群依赖闭包检查（`requires.mcp` ⊆ 纳管清单，`requires.cli` ⊆ 登记清单）。
     - 统一退出码语义（0 通过 / 1 警告与降级 / 2 严重契约阻断 / 3 执行异常）。
- **交付物**：
  - 完整的 pytest 自动化测试套件（全绿）。
  - `scripts/assets-doctor` 升级版。
- **退出门槛**：
  - 测试套件覆盖全部边界场景；故障注入测试全部通过；`assets-doctor --check` 可靠捕获各类异常。

---

### 阶段四：渐进式资产重构、验证与回滚防线

**目标**：小步慢跑、逐批实施生产配置迁移，持续以健康检查作为准出防线。

- **工作内容**：
  1. **执行速赢动作（Quick Win）**：在 `~/.grok/config.toml` 配置 `gateway_tools_enabled = false`，剥离 108 个云端工具，释放 50k+ 上下文。
  2. **试点族群迁移（Pilot）**：以 `software` 族群为试点，落地 `requires: {cli, mcp}` 声明，通过 `assets-doctor` 验证。
  3. **独立运维技能落地**：创建 `proxy-ops` 技能（梯子管理），在农场登记为 `role: standalone + load-mode: manual`，验证 Agent 可见且不占启动清单。
  4. **全机 MCP 配置收编**：通过 `mcp-apply.py` 收拢 `codegraph`、`keenable`、`vision` 至农场清单统一管理。
  5. **全族群推广与 Description 瘦身**：其余 11 族逐步补齐依赖声明；12 个入口技能的 description 精简至 300 字符以内。
  6. **指令规范收敛**：根目录 `CLAUDE.md` 设为 `AGENTS.md` 的符号链接，确立 `AGENTS.md` 为唯一指令源。
- **交付物**：
  - 生产配置全量更新。
  - `proxy-ops` 技能入库。
  - 优化后的 `AGENTS.md`。
- **退出门槛**：
  - `skills-sync --check` 全绿；
  - `assets-doctor --check` 🚨 0；
  - 5 大主流 Agent 软链正常、调用无误；
  - 核心工作流无任何回归，新会话启动 Token 大幅下降。

```

       │
       ▼

       │
       ▼
[测试与验收]   ──► Atria-Dawn-Preview 负责执行测试与真机验收
       │
       ▼
[本地 Git 审计] ──► 每阶段成果形成独立 Git Commit，确保历史可追溯、随时可回滚
```
