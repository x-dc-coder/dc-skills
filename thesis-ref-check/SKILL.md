# 论文术语一致性修正

> **职责说明**：本 skill **仅做术语一致性检查**。引用编号检查（连续性、顺序性、唯一性、尾注对应）由 `thesis-writing/scripts/check_markdown_spec.py` 自动覆盖（`_check_reference_continuity` 方法检测 REF_NUMBER_CONTINUITY / DUPLICATE / NOT_START_AT_ONE）。如需检查引用编号，请使用 thesis-writing 的 markdown spec checker：
>
> ```bash
> cd ~/projects/dc-skills && uv run python thesis-writing/scripts/check_markdown_spec.py <论文文件>
> ```

## 核心问题

处理长论文（通常 200KB+，数万字）时，上下文窗口限制导致无法一次性加载全文。
术语不一致是一个常见但难以发现的问题：同一概念在论文不同位置用了不同表述（如"虚拟社区感"vs"社区归属感"），但由于上下文截断，无法发现这种不一致。

本 skill 使用**外部状态文件法**解决：将关键信息持久化到文件中，逐章处理，确保全局术语统一。

## 工作流程

### 阶段一：预分析（不占用上下文）

使用 Bash 工具快速分析论文结构，确定章节边界。这步只输出结构信息，不读取内容。

```bash
# 如果是单文件
wc -l <论文文件>                        # 总行数
grep -n '^# ' <论文文件>               # 一级标题位置
```

**输入判断：**
- 用户可能提供一个完整文件（如 `论文初稿_完整版.md`）
- 也可能提供分章节文件（如 `chapter1.md`, `chapter2.md`...）
- 如果是后者，按文件名排序处理

### 阶段二：扫描生成术语表

创建 `_state/` 目录（与论文文件同目录），包含两个状态文件：

#### 状态文件 1: `_state/term_glossary.md`

记录论文中的关键术语及其所有变体：

```markdown
# 术语一致性表

## 体育虚拟社区
- 推荐写法: 体育虚拟社区
- 首次出现: 第1章第1节
- 发现变体:
  - 虚拟体育社区（第3章第2节）→ 建议统一
  - 体育线上社区（第5章第1节）→ 建议统一

## 持续运动行为
- 推荐写法: 持续运动行为
- 首次出现: 摘要
- 发现变体:
  - 持续性运动行为（第2章）→ 建议统一
```

**术语识别规则：**
1. 摘要中出现的关键名词短语（通常是研究的核心变量）
2. 各章节标题中的术语
3. 文中**加粗**或*斜体*强调的概念
4. 在"概念界定"章节明确定义的术语
5. 出现频率高（>5 次）的专业短语（2-6 个字）

**变体检测规则：**
- 同一语义，字数差异在 ±2 字以内
- 常见替换："的"字有无（如"社区感"vs"社区的感"）、近义词替换（如"影响"vs"作用"）、顺序调换
- 英译不一致（如"Flow"vs"心流"vs"福流"）

#### 状态文件 2: `_state/changes_log.md`

记录扫描和修正过程中的所有发现：

```markdown
# 术语修改日志

## 扫描阶段发现
- [问题] 第2章用"社群经济"，第6章用"社区经济" → 术语不一致

## 修正阶段记录
- [统一] 第6章"社区经济" → "社群经济"
```

### 阶段三：全局检查（基于状态文件）

读取 `_state/term_glossary.md`，执行以下检查：

1. 对每条术语，检查其"发现变体"列表
2. 判断变体是否为真正的错误（有些变体是有意区分，如"工具型平台"vs"社群型平台"）
3. 生成"修正计划"写入 `_state/changes_log.md`

### 阶段四：执行修正（逐章修改）

基于 `_state/` 中的分析结果，逐章修正：

**术语修正策略：**
- 以术语首次出现时的写法为准（通常摘要或第一章最规范）
- 将后续变体替换为推荐写法
- **例外**：如果变体出现在"概念辨析"或"文献综述"中，且有明确的目的（如对比不同学者的叫法），不要修改

**执行方式：**
- 逐章读取原文件 → 在内存中修正 → 写出修正后的章节到 `_state/chapterX_fixed.md`
- 修正时参考 `_state/term_glossary.md`

### 阶段五：合并输出

1. **合并修正后的章节**：按顺序合并所有 `_state/chapterX_fixed.md`
2. **生成修改报告**：基于 `_state/changes_log.md` 生成用户可读的报告

**输出文件：**
- `<原文件名>_修正版.md`：修正后的完整论文
- `<原文件名>_术语修改报告.md`：详细的术语修改说明

## 修改报告格式

```markdown
# 论文术语一致性修改报告

## 一、术语统一修正

### 1.1 已统一术语（共 X 处）
| 推荐写法 | 被替换的变体 | 所在章节 | 替换次数 |
|----------|-------------|----------|----------|
| 体育虚拟社区 | 虚拟体育社区 | 第3章 | 3 |
| 持续运动行为 | 持续性运动行为 | 第2,5章 | 5 |

### 1.2 疑似不一致（建议人工确认）
| 术语 | 变体 | 所在章节 | 说明 |
|------|------|----------|------|
| 心流体验 | 福流 | 第4章 | 可能是台湾译法，请确认是否保留 |

## 二、其他问题
（如格式不统一、标点问题等）
```

## 重要原则

1. **不要修改原文的学术内容**：只修正术语，不改变论点、数据或分析
2. **保守替换术语**：如果变体可能是故意的（如引用不同学者的不同表述），放入"疑似不一致"区域，让用户确认
3. **保留原始文件**：始终生成新文件，不要覆盖用户原文件
4. **状态文件可复用**：`_state/` 目录保留，用户下次修改同一论文时可直接增量更新
5. **分批处理**：如果论文章节超过 8 章，每处理 2-3 章后更新一次状态文件，避免上下文过长

## 边界情况处理

| 情况 | 处理方式 |
|------|----------|
| 用户只给了一章 | 只处理该章，生成部分术语表，提醒用户完整论文需全章处理 |
| 分文件输入且文件名无序 | 先读取所有文件，按内容中的章节号排序处理 |
| 论文中无明确术语体系（如纯文学评论） | 提示用户论文可能不适合术语自动检查，建议人工 Review |

## 引用编号检查（不在本 skill 范围内）

本 skill **不处理引用编号**。如需检查论文引用编号（连续性、顺序性、唯一性），请使用 thesis-writing checker：

```bash
cd ~/projects/dc-skills && uv run python thesis-writing/scripts/check_markdown_spec.py <论文文件>
```

该 checker 自动检测 REF_NUMBER_CONTINUITY（编号不连续）、DUPLICATE（重复引用）、NOT_START_AT_ONE（未从 [1] 开始）等问题。

## 示例：与用户交互流程

**用户输入：**
"帮我检查一下 `论文初稿_完整版.md`，术语好像前后不一致。"

**Skill 执行：**
1. 检查文件大小（如 257KB）→ 判断需要分块处理
2. 执行预分析（bash）→ 发现 8 章，2147 行
3. 逐章扫描 → 生成 `_state/term_glossary.md`
4. 全局检查 → 发现 5 处术语变体
5. 逐章修正 → 生成 `_state/chapterX_fixed.md`
6. 合并输出 → 生成 `论文初稿_完整版_修正版.md` + `论文初稿_完整版_术语修改报告.md`
7. 向用户汇报修改概况，提供报告摘要
