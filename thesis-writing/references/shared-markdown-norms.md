# Markdown 撰写规范（模式无关共享部分）

本文件包含本科毕设模式与期刊论文模式共享的 Markdown 机械化规范。两模式各自特有的规范（字数、引文风格、章节模板等）见对应的 `undergrad-*-*.md` 或 `journal-*-*.md` 文件。

## 编码与文件格式

- 文件必须使用 **UTF-8 无 BOM** 编码
- 行尾统一使用 LF（Unix 风格），避免 CRLF
- 禁止 YAML front matter 元信息区块（`---` 开头）
- 禁止 Pandoc 标题元信息块（`%` 开头）
- 正文前 40 行内禁止出现 `Key: Value` 格式的元信息字段

## 标题规范

### Markdown 标题语法

- 必须使用 ATX 标题风格（`#` / `##` / `###`），禁止使用 Setext 风格（`===` 或 `---`）
- **一级标题** `#`：用于章节和特殊标题（摘要/Abstract/参考文献/致谢/Keywords 等）
- **二级标题** `##`：必须包含编号，格式为 `数字.数字 标题`（如 `## 1.1 研究背景`）
- **三级标题** `###`：必须包含编号，格式为 `数字.数字.数字 标题`（如 `### 1.1.1 国内现状`）
- 标题层级必须连续，禁止跳级（如 `#` 之后不能直接跟 `###`）
- 编号必须前后一致：二级标题的首数字必须匹配当前一级标题的章节号；三级标题的前两位数字必须匹配当前二级标题编号
- **禁止**在 Markdown 正文中使用一级标题书写论文题目（题目应由封面或 LaTeX 模板提供）
- 文档必须至少有一个一级标题

### 编号连续性（ERROR 级别）

- 一级标题编号必须连续，从 1 开始，不得重复或跳号
- 同一章节内的二级标题编号必须连续，从 1 开始，不得重复或跳号
- 同一小节内的三级标题编号必须连续，从 1 开始，不得重复或跳号

### 格式一致性（WARN 级别）

- 同一级别的标题应使用统一的编号格式（如全用 `1.` 还是 `（1）`），混用会触发警告
- 建议全文各级标题格式保持一致

## 图片格式

- **必须使用 Markdown 语法**：`![图X-X 标题](./path/to/image.png)`
- 图片标题格式：`图X-Y 标题`（章节式编号，如"图3-1 系统功能结构图"）或 `图N 标题`（全局编号）。同一文档建议统一
- 图片标题前缀支持：`图`、`Figure`、`Fig.`、`Fi.`
- **禁止使用 HTML `<img>` 标签**
- **禁止在图片下方重复添加标题文字**（如 `**图3-1 系统功能结构图**`），标题应仅在图片的 `alt` 属性中体现
- 图片 alt 不能为空，必须包含图题
- **禁止将公式以图片形式插入**（alt 中包含"公式"/"equation"/"formula"等关键词会触发 ERROR）
- 图片前后必须有段落文字描述（前或后至少一侧），否则触发 ERROR：`MISSING_TEXT_AROUND_IMAGE`
- 本地图片路径必须存在（检查时会验证），不存在的路径触发 WARN
- 全文插图按每章单独编序，编号必须连续，不得重复或跳缺
- 图应放在离正文首次出现处的近处，先文后图

## 表格格式

- 使用标准 Markdown 表格语法
- 表格前必须有规范表题：`表X-X 标题`（章节式编号）或 `表N 标题`（全局编号）。两种编号方式均可，但同一文档建议统一
- 表题支持加粗标记：`**表1-1 标题**` — checker 会自动去除 `**` 后匹配
- 表题与表格之间不要有空行
- 表格前后必须有段落文字描述（前或后至少一侧），否则触发 ERROR：`MISSING_TEXT_AROUND_TABLE`
- 表格编号必须连续，章节号必须与当前章节一致
- **表格各行列数必须一致**（表头/数据行列数应相同），否则 ERROR：`TABLE_COLUMN_MISMATCH`
- 列数检查只对**单元格末尾的有效合并**豁免（colspan>1 或 rowspan>1）：`数据<<2后续`、`<<1`、普通文本里的 `<<`/`^^`、裸 `^^` 都不豁免，仍报 `TABLE_COLUMN_MISMATCH`
- 表格应放在离正文首次出现处的近处，先文后表

### 表格合并语法（可选）

友好合并语法（markdown 表格 + `<<N`/`^^N` 标记）。**导出侧默认关闭**：只有学校配置写 `table.merge_syntax: true` 时才会翻译成合并单元格，默认配置下这些标记按字面文字导出（issue #66 防误解析）。论文稿使用前先确认目标 profile 已开启。

```markdown
| 表头一 | 表头二 | 表头三 |
|:---|:---|:---|
| 跨两列<<2 | 内容 |
| 续行^^ | 内容二 |
```

- `内容<<N`：向右跨 N 列；`内容^^N`：向下跨 N 行；裸 `^^`：续接上一行合并单元格。标记必须锚定在单元格**末尾**，`数据<<2后续` 不会被当作合并
- 合并语法需合法：跨列不越界（`MERGE_COLSPAN_EXCEED`）、跨行不越界（`MERGE_ROWSPAN_EXCEED`）、首行不得出现裸 `^^`（`MERGE_ROWSPAN_ORPHAN`）

## 代码块规范

- 代码块使用 fence（```）包裹，**必须成对闭合**（起始与结束 fence 各占一行），否则 ERROR：`FENCE_UNCLOSED`
- Mermaid 代码块会触发 WARN：`MERMAID_DISABLED`（当前流程不渲染）
- 代码块样式（等宽字体/灰底）由导出配置控制，撰写阶段无需关注

## 数学公式规范

- 行内公式使用 `$...$` 语法，如 `$E=mc^2$`
- 独立公式使用 `$$...$$` 语法；**块级公式必须成对闭合**（起始 `$$` 与结束 `$$` 各占一行），否则 ERROR：`MATH_BLOCK_UNCLOSED`
- 公式编号格式：`(X-Y)`，X 为章节号，Y 为章内顺序号。可使用 `\tag{X-Y}` 置于公式右侧
- 全文公式按每章单独编序，编号必须连续，不得重复或跳缺
- **禁止将公式以图片形式插入**（如公式截图），必须使用 LaTeX 数学语法书写

## 段内换行与分隔线规范

- 禁止段内换行（行末两个空格），应使用空行分隔段落（否则 ERROR：`INTRAPARAGRAPH_LINE_BREAK`）
- 禁止使用 `<br>` 标签换行（否则 ERROR：`HTML_LINE_BREAK`）
- 禁止使用单独一行的 `---` 作为水平分割线：Words-Production 导出流水线预处理会将单独一行的 `---` 换为空行，不会被渲染为水平分割线；请使用规范的各级 ATX 标题组织内容

## Mermaid 代码块

- Words-Production 导出流水线预处理会主动剥除 ```mermaid 代码块（大小写不敏感、``` 与 mermaid 间允许空白）；正文中保留此类代码块会触发 WARN：`MERMAID_DISABLED`
- 应先将 Mermaid 渲染为图片后引用（通过 diagram 技能出图），或在导出前删除
- `~~~mermaid` 不会被自动剥除，但 pandoc 不会自动渲染为矢量图，仍建议转为图片格式插入

## Markdown 标记成对检查

脚本会自动检查以下标记是否成对出现（不匹配则 ERROR）：

- 加粗 `**`
- 斜体 `*`
- 删除线 `~~`
- 行内代码 `` ` ``
- 方括号 `[]`
- 圆括号 `()`
- ASCII 双引号 `"`
- 中文双引号 `"` / `"`

## 空格规范（写作约定，非自动检查）

> **注意**：`check_markdown_spec.py` 目前**不检查**中英文之间的空格。以下为写作约定，需在撰写时自觉遵守。

- **正文中，中文字符与英文字母/数字之间不得有空格**
- 正确：`基于SpringBoot框架` / `MySQL 8.0数据库` / `Vue.js前端`
- 错误：`基于 SpringBoot 框架` / `MySQL 8.0 数据库` / `Vue.js 前端`
- 英文单词**内部**空格保留（如 `Spring Boot`、`RESTful API`）
- 行内代码、URL、参考文献列表中的 `[数字]` 不受此限制
