# WSL 跑 Windows 实验：调研报告与推荐方案（2026-08-18）

## 1. 为什么桥接启动会短暂出现控制台

| 原因 | 机制 | 是否可避免 |
|:---|:---|:---|
| python.exe（控制台子系统程序） | Windows 为控制台程序绑定 conhost.exe 宿主，窗口闪现；即使输出重定向也先建控制台 | 必弹，改用 pythonw.exe |
| cmd.exe /c 中转 | cmd 本身是控制台宿主，且会再拉起子控制台 | 能避免：pythonw 直调不经 cmd |
| WSL interop 的 conhost 宿主化 | WSL 经 /init → wslhost.exe → CreateProcess 启动控制台程序时附加 conhost | 仅控制台程序触发，pythonw(GUI) 不受影响 |
| multiprocessing spawn / subprocess 派生子进程 | 子进程用 sys.executable；若主进程是 python.exe，子进程也弹窗 | 全程 pythonw 则子进程也 pythonw |

**结论**：弹窗的根源是**用了控制台子系统程序（python.exe / cmd.exe）**。GUI 子系统程序 pythonw.exe 永不弹窗。

## 2. pythonw 的两个隐藏坑（比弹窗更隐蔽）

1. **sys.stdout = None**：pythonw 下 Python 解释器不绑定 stdio，print() 抛异常且 traceback 丢失（看似'卡住'）。
   → 修复：worker 内显式 `sys.stdout = sys.stderr = open(log, 'a', encoding='utf-8', buffering=1)`，且日志用 **Windows 路径**。
2. **C 库写 fd 1**（HiGHS/OR-Tools 等）：pythonw 下 fd 1 默认无效句柄，C 库写日志可能阻塞。
   → 修复：milp options 加 `output_flag: False`（HiGHS 不再写日志）；且 Popen 侧 `stdout=文件` 重定向 fd 1。

## 3. skill（wsl-windows-bridge）审查结论

| skill 能力 | 弹窗 | 可靠性 | 评价
|:---|:---:|:---:|:---|
| pythonw.exe 直调（文档推荐） | 无 | 高 | ⭐ 首选，但需自行处理 stdio/路径 |
| run_gpu_windows | 弹（cmd.exe+python.exe） | 中 | ⚠️ 与'pythonw 优先'原则矛盾，应改默认 pythonw |
| stream_gpu_windows | 看传参（pythonw 则无） | 高 | ⭐ 流式、tqdm 清洗、超时管理 |
| launch_detached | 无（wslpath+stdio 绑定+pw） | 高 | ⭐⭐ 实测可用：后台+日志(/tmp/gpu-logs)+PID+断点 |
| win-launcher.py（Job Object） | 无 | 高 | ⭐ 防孤儿：KILL_ON_JOB_CLOSE 自动清子进程 |
| _resolve_wsl_py_exe | — | — | ⭐ WSL 侧 subprocess 启动 Windows exe 的路径转换 |

**结论**：skill 骨架优秀（launch_detached / stream_gpu_windows / win-launcher 已解决 stdio、路径、防孤儿、流式），但 **run_gpu_windows 应改为默认 pythonw + 不经 cmd.exe**。

## 4. 推荐架构（三层，按场景选择）

### L1 快速验证（一条命令，阻塞）

```python
    capture_output=True, text=True, encoding='utf-8', errors='replace',
    timeout=1800, env={**os.environ, 'PYTHONUTF8':'1','PYTHONIOENCODING':'utf-8'},
    cwd='/mnt/e/temp',  # 必须 /mnt/ 下

EOF
```

### L2 后台实验 / 批处理（launch_detached + batch worker）
- 写 `batch_worker.py`：单进程内循环处理多个任务（避免频繁启停 + 调度器收割不可靠）
- 用 skill `launch_detached(py_exe=pythonw.exe, code=..., job_name=..., use_wrapper=True)` 启动
- 结果 JSON 行追加到共享盘文件；日志到 /tmp/gpu-logs（inotify 实时 tail）

### L3 GPU 训练（gpu_safe_subprocess 全家桶）
- `stream_gpu_windows`（实时进度）/ `launch_detached`（后台）/ `GpuLimits`（显存+线程栅栏）

## 5. 铁律清单

1. **全程 pythonw.exe**（含 worker、spawn、子进程），绝不用 python.exe 做任务
2. worker 内显式绑定 `sys.stdout/stderr` 到日志（Windows 路径），防静默丢失
3. WSL bash/Python → Windows 进程，**路径必须 wslpath -w**（/mnt/e/... → E:\...）
4. 高精度求解器（HiGHS 等）**禁日志输出**（output_flag=False），防 fd 阻塞
5. Popen 启动 Windows 进程时 **stdout/stderr 重定向到文件**（C 库写 fd 1 需要有效句柄）
6. 多任务用 **batch worker 内部循环**（每算例一进程的开销/调度问题多）
7. `worker 慢 ≠ 卡住`：先看 CPU 时间是否增长再下结论
8. 调度/常驻进程**必须单实例**（pkill 会自杀，用 pgrep 排除自身）
9. MIP `res.x` 可能为 None（HiGHS status 2/3/4）→ 必须防护，防数据静默丢失
10. 长任务用 `launch_detached`（会话关闭不中断）+ `use_wrapper`（防孤儿）
